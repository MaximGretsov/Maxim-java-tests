# Дизайн API тест-кейсов - Итерация 2

## Описание

В данном репозитории находится JSON-выгрузка Postman-коллекции для проверки API в рамках итерации 2.

Коллекция покрывает следующие блоки:

1. Депозит денег пользователем
2. Перевод денег с одного аккаунта на другой
3. Изменение имени пользователя в профиле

Файл коллекции содержит набор позитивных и негативных тест-кейсов, а также проверки авторизации, валидации входных данных и базовой корректности работы API.

## Предусловия

Перед запуском основных тестов необходимо подготовить тестовые данные.

### 1. Получение токена администратора

Сначала необходимо выполнить запрос:

```text
Get admin's token
```

После выполнения запроса нужно сохранить значение заголовка:

```text
Authorization
```

Полученный токен администратора используется для создания тестовых пользователей.

### 2. Создание тестовых пользователей

Далее с использованием токена администратора необходимо создать двух пользователей.

Для этого используется запрос:

```text
Create User
```

После создания пользователей необходимо сохранить их логины и пароли, так как они понадобятся для дальнейшей авторизации.

### 3. Авторизация пользователей

После создания пользователей необходимо выполнить авторизацию для каждого из них.

Для этого используется запрос:

```text
Login
```

После успешной авторизации нужно сохранить значение заголовка:

```text
Authorization
```

Токены авторизации пользователей будут использоваться в дальнейших запросах к API.

### 4. Создание аккаунтов пользователей

После авторизации необходимо создать аккаунты для пользователей.

Для этого используется запрос:

```text
Create account
```

Необходимо подготовить следующие данные:

* для первого пользователя создать 2 аккаунта
* для второго пользователя создать 1 аккаунт

После создания аккаунтов нужно сохранить их `id`, так как они используются в тестах депозита и перевода денег.

### 5. Проверка созданных аккаунтов

Созданные аккаунты можно проверить с помощью запроса:

```text
Customer accounts
```

Запрос необходимо выполнить с токеном каждого из пользователей, чтобы убедиться, что аккаунты были созданы корректно.

## Порядок выполнения

Рекомендуемый порядок работы с коллекцией:

1. Выполнить запрос `Get admin's token`
2. Выполнить запрос `Create User` для создания тестовых пользователей
3. Выполнить запрос `Login` для каждого пользователя
4. Выполнить запрос `Create account` для создания аккаунтов
5. Проверить созданные аккаунты через `Customer accounts`
6. После выполнения предусловий перейти к тестам по основным блокам:

   * `Deposit`
   * `Transfer`
   * `Change name in profile`

## Основные блоки тестирования

### Deposit

В блоке `Deposit` проверяется пополнение аккаунта пользователя.

Проверки включают:

* успешное пополнение аккаунта
* пополнение минимальной допустимой суммой
* пополнение максимальной допустимой суммой
* попытку пополнения нулевой суммой
* попытку пополнения отрицательной суммой
* попытку пополнения суммы выше максимально допустимой
* попытку пополнения чужого аккаунта
* попытку пополнения несуществующего аккаунта
* проверку обязательности поля `id`
* проверку обязательности поля `balance`
* проверку некорректных типов данных
* проверку авторизации
* проверку создания транзакции после депозита

### Transfer

В блоке `Transfer` проверяется перевод денег с одного аккаунта на другой.

Проверки включают:

* успешный перевод между аккаунтами пользователя
* перевод минимальной допустимой суммы
* перевод максимальной допустимой суммы
* попытку перевода нулевой суммы
* попытку перевода отрицательной суммы
* попытку перевода суммы выше максимально допустимой
* попытку перевода суммы больше баланса отправителя
* попытку перевода с чужого аккаунта
* попытку перевода с несуществующего аккаунта
* попытку перевода на несуществующий аккаунт
* проверку обязательных полей
* проверку некорректных типов данных
* проверку авторизации
* проверку создания транзакции после перевода

### Change name in profile

В блоке `Change name in profile` проверяется изменение имени пользователя в профиле.

Проверки включают:

* успешное изменение имени
* проверку имени, состоящего только из букв и пробелов
* проверку пустого значения
* проверку пробела в начале имени
* проверку пробела в конце имени
* проверку имени, состоящего только из пробелов
* проверку специальных символов
* проверку цифр в имени
* проверку дефиса в имени
* проверку двойного пробела между словами
* проверку значения `null`
* проверку отсутствующего поля `name`
* проверку изменения имени без авторизации
* проверку изменения имени с некорректной авторизацией

## Примечание

Перед выполнением тестов необходимо убедиться, что в запросах используются актуальные токены авторизации и корректные `id` созданных аккаунтов.

Коллекция предназначена для ручного запуска API тест-кейсов в Postman.
